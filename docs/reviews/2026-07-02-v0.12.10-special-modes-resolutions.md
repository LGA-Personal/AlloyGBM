## 1. Critical correctness issues

### 1.1 Row subsampling / GOSS committed predictions

**Fixed in pending v0.12.11 PR by `9d93ad6`; optimized without changing that correction in PR #129 by
[`3538e3d`](https://github.com/LGA-Personal/AlloyGBM/commit/3538e3db633bf7f806111b95eddc93cf1c1c951a).**
The original repair rebuilt candidate training predictions by walking accepted trees over every
training row, keeping uniform-subsample and GOSS committed state consistent with artifact
inference. Eligible scalar and multiclass standard/GOSS rounds now retain that invariant by reusing
builder deltas for selected rows and replaying only excluded rows. DART and quantile refinement
retain their existing full-replay lifecycle, while joint multi-output training retains its
independent path.

Both shared full-tree replay and restricted replay now read the matrix's logical missing-bin value
rather than assuming the u8 missing sentinel. That separate correctness correction makes u16
missing values follow the learned `default_left` route, matching predictor behavior; it is covered
independently and is not an attributed timing result. It applies to DART and quantile full replay as
well as to the optimized standard/GOSS path.

## 2. MorphBoost

**Partially fixed in pending v0.12.11 PR.** The scalar tree builders, joint tree scaling, and
quantile leaf-refinement path now share `MorphState::leaf_scale_for_depth` for the
learning-rate schedule, per-iteration shrinkage, and depth-penalty multiplier. This removes the
manual duplication flagged in §2.4 while preserving PL-leaf coefficient scaling.

Regression coverage:

- `crates/engine/src/tests/morph_state.rs::morph_leaf_scale_matches_schedule_shrinkage_and_depth_penalty`

**Further narrowed in pending PR.** The post-warmup gain now makes both blend inputs
dimensionless. The raw XGBoost split gain is divided by
`(parent_hessian + lambda_l2) * ema_grad_std^2`; the information score's logarithmic factor now
uses the same EMA-standardized gradient. This keeps `info_score_weight` meaningful across node
sizes and uniform gradient/target rescaling. The blend is convex at every post-warmup iteration:
the effective information coefficient is `info_score_weight * morph_weight` and the gradient
coefficient is its complement. Warmup remains pure standard gain, including no balance penalty.

`MorphPrecomputed::for_iteration` now receives the full fit horizon. Its ramp is
`tanh(3 * iteration / total_iterations)`, so it reaches its main transition around one third of
the requested fit rather than saturating after a fixed number of rounds. Scalar and joint paths
use the same normalized formula.

The existing `benchmarks/morph_ablation.py` now has a deterministic `--gate` A/B check against
the matching `training_mode="auto"` model. It fails on non-finite results or a material
regression (error ratio above `1.35`, or accuracy decline greater than `0.08`). The calibrated
default `info_score_weight` is now `0.1`, reduced from `0.3` because normalizing the gradient
term makes the old value materially more aggressive. Fixed-seed calibration evidence:

| --- | ---: | ---: | ---: | ---: |

| Regression RMSE | 1.73227 | **1.70216** | 1.80743 | 2.01308 |

## 3. DRO leaves

**Partially fixed in PR #108.** Public estimator and quickstart documentation now
defines `dro_radius` in the implemented units: it is a per-standard-error
multiplier whose threshold contribution is `radius * sqrt(n) * sigma(g)` on a
leaf gradient sum, equivalently `radius * sigma(g) / sqrt(n)` on the gradient
mean. The docs also make the remaining scale dependence explicit: the radius
interacts with the objective/target scale and `lambda_l1`, so `0.05` is a
baseline to tune on validation data, not a transferable robustness guarantee.

`benchmarks/dro_robustness.py` adds a deterministic, offline clean-holdout
experiment for both `GBMRegressor` and
`MultiLabelGBMRanker(multi_label_mode="joint")`. It fits 100-tree depth-4
models on clean and 12%-outlier-contaminated labels for five fixed seeds, then
measures RMSE against uncorrupted held-out targets. The committed report is
[`docs/benchmarks/dro_robustness_v1.md`](../benchmarks/dro_robustness_v1.md).

Median results at `dro_radius=0.05`:

| Path | Solver | Clean-label-fit RMSE | Contaminated-label-fit RMSE | Corruption penalty |
| --- | --- | ---: | ---: | ---: |
| scalar | standard | 0.73269 | 0.97510 | +0.22875 |
| scalar | DRO | 0.71300 | 1.01008 | +0.23433 |
| joint | standard | 0.78446 | 0.86088 | +0.05724 |
| joint | DRO | 0.78346 | 0.86901 | +0.06435 |

This fixture does not show a default-radius robustness gain: the median
corruption penalty is slightly larger for DRO on both paths. The joint result
therefore does not justify adding per-bin gradient-square state and roughly
1.5x joint-histogram memory for robust split selection. Joint DRO remains a
leaf-only opt-in, documented as such; future work should be driven by a
representative downstream workload rather than extending the histogram now.

**Fixed in PR #133.** Active scalar-model numeric DRO split selection now uses an
exhaustive safe four-lane SIMD scanner for the f64 variance/radius term while
preserving the scalar formula, threshold order, missing directions, child
statistics, and gain tolerance. Native categorical, factor-penalized, and
Morph+DRO scans retain scalar fallbacks; joint DRO remains leaf-only. The
benchmark report is [`dro_simd_pr133.md`](../benchmarks/dro_simd_pr133.md).
The corrected same-host evidence passes the declared end-to-end fallback at
`26.3244%` despite the 64-bin scanner case remaining below 1.5x; the 255-bin
case reaches 1.510x. The strict standard-arm gate uses the worst five-seed
per-dataset median (`1.011813`, below `1.03`), while the worst individual record
ratio (`1.127643`) remains descriptive. These timing results do not change the
correctness or fallback scope of this resolution.

## 5. Factor neutralization

**Partially fixed in pending v0.12.11 PR.** Objective-dependence is now documented: per-round
gradient neutralization projects gradients while leaving Hessians unchanged, so non-constant
Hessian objectives do not produce a simple projection of unneutralized leaf values. Fitted scalar
estimators and joint `MultiLabelGBMRanker` now add post-fit prediction exposure diagnostics to
`factor_exposure_diagnostics_`: `prediction_exposure_dot`, `prediction_exposure_abs`, and
`prediction_exposure_l2`, computed from transformed fit-time exposures and fitted training
predictions. Multiclass models have no single scalar prediction vector, so they keep the
transform/means/stds metadata but omit the prediction-exposure entries.

**Further narrowed in pending v0.12.11 PR.** Active `split_penalty`
neutralization now resolves the default `factor_exposure_transform="none"` to an effective
`"standardize"` transform when `factor_penalty > 0`, while `per_round_gradient`, `pre_target`,
and inert split-penalty configurations still default to no transform.

**Further narrowed in pending v0.12.11 PR.** Scalar CPU native-categorical `split_penalty`
candidates now share the numeric path's prefix-sum treatment. The backend precomputes per-category
factor exposure sums once in the Fisher-sorted category order, then advances the prefix in O(K)
per candidate instead of rescanning node rows for each prefix and missing-direction candidate.

**Further narrowed in pending v0.12.11 PR.** Scalar CPU factor split scoring now reuses a
thread-local `FactorSplitScratch` buffer for each feature scan when a factor context is active,
matching the existing histogram arena pattern and avoiding per-feature scratch Vec allocation
churn.

**Further narrowed in pending v0.12.11 PR.** `FactorProjector` now parallelizes the fit-time
Gram build, per-round RHS accumulation, and residual-write passes over rows. Repeated scalar,
multiclass, and joint per-round gradient projection call sites now pass a reusable residual
scratch buffer instead of allocating one projection vector per output/round.

## 6. Objectives

### 6.1 Ranking gradient optimizations

**Partially fixed in pending v0.12.11 PR.** Ranking objective gradient computation now runs
query groups independently with Rayon for `rank:pairwise`, `rank:ndcg`, `rank:xendcg`, and
`yetirank`. NDCG-weighted pairwise objectives also precompute per-document gains and
rank discounts once per group/per permutation instead of recomputing `powf` and `log2`
inside each pair loop. `LambdaMARTObjective::compute_gradients_into` now fills the caller's
buffer directly rather than allocating a temporary gradient vector, while preserving the
existing `GradientPair::new` validation behavior.

**Further narrowed in pending v0.12.11 PR.** Single-output `GBMRanker` now exposes
`ranking_sigma` for pairwise ranking-family objectives. The Rust `rank:pairwise`,
`rank:ndcg`, and `yetirank` objectives validate positive finite sigma values and apply the
standard logistic sharpness scaling to pairwise gradients and Hessians, while defaulting to
`1.0` for backward-compatible behavior.

**Further narrowed in pending v0.12.11 PR.** Joint `MultiLabelGBMRanker` now accepts the same
`ranking_sigma` kwarg when `multi_label_mode="joint"`. The PyO3 bridge forwards the positive
finite sigma into joint `rank:pairwise` and `rank:ndcg` objectives, and the Rust joint objective
variants carry it through per-output gradient computation. The default remains `1.0`, preserving
existing joint ranking fits.

**Further narrowed in pending v0.12.11 PR.** `GBMRanker` and joint
`MultiLabelGBMRanker` now expose `lambdarank_truncation_level` for `rank:ndcg`. When set, the
LambdaMART pair loop only scores pairs where at least one document is currently in the top-k
positions for its query. `None` preserves the previous all-pairs behavior, and invalid values
(`0` or non-integers) are rejected at the Python boundary and in the Rust objective constructor.

**Further narrowed in pending v0.12.11 PR.** `GBMRanker` and joint
`MultiLabelGBMRanker` now expose `lambdarank_normalize` for `rank:ndcg`. When enabled, each query's
LambdaMART pair weights use score-distance regularization and the accumulated lambdas/Hessians are
rescaled by the query-local `log2(1 + sum_lambdas) / sum_lambdas` factor. The default remains
`False` for backward-compatible training behavior.

### 6.2 GLM stabilizers and f64 accumulators

**Partially fixed in pending v0.12.11 PR by `97ed521` and follow-up PR by
[`abc5ef7`](https://github.com/LGA-Personal/AlloyGBM/commit/abc5ef7) (merged with clippy-cleanup
[`4b58f7c`](https://github.com/LGA-Personal/AlloyGBM/commit/4b58f7c)).** GLM initial predictions
now compute weighted target means with f64 accumulators, and Poisson/Gamma/Tweedie objective
losses now accumulate telemetry in f64 before returning f32. The Poisson objective also inflates
its Newton hessian by `exp(0.7)` by default, matching the standard Poisson max-delta-step
stabilizer, and exposes `poisson_max_delta_step` on `GBMRegressor`, `GBMRanker`, independent
and joint `MultiLabelGBMRanker`, and the native Rust `TrainParams`/objective path.

The tunable step is carried as a `max_delta_step` field on `PoissonObjective` itself (defaulting
to 0.7 via `Default`); the initial parallel `TunedPoissonObjective` type was removed in `4b58f7c`
because its `PoissonObjective::new(..)` returned a different type and tripped
`clippy::new_ret_no_self` under `-D warnings`. `new(..)` now returns `Self`.

### 6.3 Quantile

**Partially fixed in PR #109.** The weighted `weighted_quantile` path no
longer sorts every leaf. It now selects a median-by-count pivot, partitions the
active `(value, weight)` range into less-than, equal-to, and greater-than groups,
and follows only the group containing the weighted threshold. The partition
keeps f64 weight sums and preserves the existing contract: return the first
value whose cumulative positive weight reaches `alpha * total_weight`.

Regression coverage:

- `crates/engine/src/objectives/quantile.rs::tests::weighted_quantile_matches_sorted_reference_at_ties_and_weight_boundaries`
  compares the selector with the former sorted reference at duplicate values and
  exact cumulative-weight boundaries.
- `crates/engine/src/objectives/quantile.rs::tests::weighted_quantile_partitions_large_leaves_in_linear_work`
  uses 65,537 weighted values and asserts the selector's partition loop visits
  fewer than twice the input rows, a deterministic O(n) guard that avoids a
  timing-sensitive unit test.

**Benchmarked; production follow-up not supported by this evidence.**
[`benchmarks/review_guardrails.py`](../../benchmarks/review_guardrails.py)
now compares the current L2-proxy split criterion with two smoothed-pinball
criteria on deterministic heteroscedastic train/holdout fixtures. The committed
full report is
[`docs/benchmarks/review_guardrails_v1.md`](../benchmarks/review_guardrails_v1.md).

Across seeds `7, 13, 29`, every quantile arm passes the 1.10x no-split-loss
gate (maximum ratio `0.994`). The two smoothed arms tie: each has an overall
median held-out pinball loss of exactly `0.04010663203691039` (reported with an
absolute tie tolerance of `1e-12`). Neither improves the proxy arm's median
held-out pinball loss at alpha `0.10` or `0.50`; both tie it at `0.90`. This
resolves the requested split-selection benchmarking and supplies decision
evidence only: it does not implement smoothed pinball or justify a production
smoothing/default-parameter follow-up.

different categorical partition instead of subtracting a row-scanned penalty only after the
unpenalized best partition was chosen.

**Further narrowed in pending v0.12.11 PR.** The review-requested joint `row_subsample=0.5`
