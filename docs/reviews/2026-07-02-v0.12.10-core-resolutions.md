### 1.1 Split-search enforcement for leaf row/hessian constraints

**Fixed in pending v0.12.11 PR.** Split scanners now enforce both child row-count and

### 1.2 Default quantile binning

**Fixed in pending v0.12.11 PR.** The Python estimator default for
`continuous_binning_strategy` is now `"quantile"` for `GBMRegressor` and inherited
`GBMClassifier` / `GBMRanker` fits. `MultiLabelGBMRanker` also defaults its continuous-binning
property and joint-mode metadata to `"quantile"` so both independent and joint modes follow the
same default. Explicit `"linear"` and `"rank"` settings remain available.

The joint trainer now threads `continuous_binning_strategy` and `continuous_binning_max_bins`
through `train_joint_multi_label_ranker` instead of hard-coding equal-width (`Linear`) binning.
Previously joint training always binned continuous features linearly while the prediction path
quantized them with the configured strategy; under the new quantile default this produced a
train/predict binning mismatch that corrupted joint predictions on skewed features. The redundant
`max_bin` bridge argument was removed, and `continuous_binning_max_bins` falls back to the legacy
`max_bin` kwarg so joint fits that only set `max_bin` keep a consistent train/predict bin count.

The default switch also exposed and fixed a multiclass warm-start offset bug: resumed multiclass
fits now infer completed rounds from the maximum encoded tree id across all class stump streams,
not only class 0. This prevents continuation from reusing tree ids when one class stops producing
splits before another under quantile binning.

### 1.4 Monotone constraint bounds propagation

**Resolved on 2026-07-28 in the pending v0.12.11 implementation series.**
The [approved design](../benchmarks/monotone_bound_propagation_design.md)
replaces post-hoc sibling rejection with inherited finite scalar-output
intervals. Each active node starts within the root interval, clamps raw child
outputs to its inherited interval, and, for a constrained numeric split,
partitions the interval at a finite f64 midpoint. Increasing splits assign the
lower interval to the left child and the upper interval to the right child;
decreasing splits reverse those assignments. Reversed scalar children meet at
that midpoint rather than losing the split. Level-wise and leaf-wise builders
both carry the child intervals to descendants.

Basic split scoring remains the existing unbounded-gain calculation. Projection
is applied only after a candidate split is accepted, and the final
parent-relative scalar deltas reconstruct inside their inherited intervals.
Quantile and experimental regression leaf refinement project affected trees
before predictions are rebuilt. Constrained warm starts validate the retained
forest before adding rounds: compliant same-version prefixes are unchanged,
while a legacy prefix that would require projection is rejected. No artifact
section, metadata field, schema version, or public parameter changed.
Public Rust prediction now matches compact artifact arithmetic by evaluating
each selected path into a zero-based local f32 tree contribution before adding
that completed contribution once to the model baseline. Stumps are ordered by
decoded tree ID and then local node ID, so arbitrary public stump ordering is
accumulated root-to-leaf and matches compact prediction; artifact bytes and
compact encoding are unchanged.

The public guarantee is intentionally narrow: final scalar predictions are
non-decreasing for ``+1`` and non-increasing for ``-1`` when only the
constrained feature changes between finite numeric values. Missing values route
through learned branches and are unordered relative to numeric values. Binary
positive-class probabilities inherit the order because sigmoid is
order-preserving. Standard and GOSS scalar ensembles are covered. Active
constraints reject DART, linear leaves, multiclass softmax, and native
categorical splits on the constrained feature. DART predictor weights can
change exact f32 ordering after tree projection, so neither transient dropout
predictions nor final weighted DART predictions carry the guarantee. Empty or
all-zero constraints remain valid with ordinary DART behavior unchanged.
Constrained warm starts reject retained non-unit DART weights even when the
resumed fit selects standard boosting, preventing weighted artifacts from
bypassing that compatibility limit.
Joint multi-output training continues to reject active monotone constraints
through its existing public `NotImplementedError`; that unsupported combination
is unchanged and was not implemented by this work.

The full [acceptance report](../benchmarks/monotone_constraints_v1.md) was
regenerated with the approved methodology at
`72e4709b9706127a7191e51bfe40228515d3b05b`: 216 of 216 records completed,
all finite grid evidence covered 884,736 adjacent pairs, and there were zero
monotone violations. The matrix uses exact training-row counts `128`, `4,096`,
and `32,768`, an independent bounded 512-to-4,096-row holdout, and shared
`max_depth=3` / `min_data_in_leaf=8`. Regression constrained to unconstrained
loss ratios ranged from `0.967510` to `1.040077`; binary error degradation
ranged from `-0.048828` to `0.013672`; both meet the `1.25` and `0.08` gates.
Fit-time ratios ranged from `0.721491` to `1.360469` and remain descriptive
only. The gate also requires the exact canonical scenario order, scenario
specifications, rounds, contexts, record metadata, checked-pair count, and a
full lowercase 40-character benchmark source commit.

### 1.7 Low-hanging accuracy features

**Partially fixed in pending v0.12.11 PRs.** [Approximate quantile sketches](../roadmap/current.md#approximate-quantile-sketches)
are implemented behind the opt-in `quantile_sketch_max_rows` row cap. Large fits sample evenly
distributed rows deterministically; `None` and row counts at or below the cap preserve exact
full-column cuts. Native metadata and `feature_quantile_cut_methods_` keep training, prediction,
joint multi-output fits, and persistence on one cut set. The full 1,000,000 x 16 gate held
mean/p99/max rank error to 0.001132/0.003974/0.004347 and RMSE to 1.002x while reducing bridge
preparation to 0.294x and incremental fit RSS by 64.50 MiB. See the
[candidate evidence](../benchmarks/architectural_backlog_v1.md#approximate-quantile-sketch-candidate).

[Exclusive Feature Bundling (EFB)](../roadmap/current.md#exclusive-feature-bundling-efb)
is also implemented behind opt-in `feature_bundling="exact"`. Deterministic
zero-conflict bundles retain original feature identities and produce
byte-identical artifacts and predictions. Conflicted validation data and
excluded feature classes fall back or skip without weakening categorical,
monotone, or interaction semantics. The full candidate reduced 512 one-hot
features to 32 physical columns, improving native training by 33.3% and total
fit by 21.3%; dense data remained inactive with no regression. See the
[candidate evidence](../benchmarks/architectural_backlog_v1.md#exclusive-feature-bundling-candidate).

Per-node/per-level column sampling and additional GOSS-rate work remain open
separately.

### 2.4 Histogram and partition allocation pools

**Resolved in the pending v0.12.11 implementation series.** Tree construction now reuses the
allocations already owned by each consumed parent node instead of introducing a process-wide pool.
For sibling histograms, the larger child takes ownership of the parent `HistogramBundle` and
subtracts the independently built smaller child in place. For row partitions, the ownership-aware
backend path consumes the parent row vector, preserves stable left/right row order and the existing
parallel statistic-reduction order, and reuses that allocation for one child while allocating only
the other. The default `BackendOps` implementation retains the prior borrowed behavior for other
backends.

Standard numeric SIMD split scans also keep their three prefix arrays in worker-local reusable
scratch. Nested calls fail explicitly instead of aliasing storage, and panic recovery leaves the
scratch usable. Scalar, categorical, DRO, MorphBoost, PL, and factor-neutral scanners retain their
existing paths. There is no Python API or artifact-format change. The internal Rust-facing
`BackendOps` trait gains one additive method with a backward-compatible default implementation.

This closes the concrete repeated-allocation finding without a global range-based `DataPartition`
rewrite. Such a rewrite would change row ownership throughout the trainer and is not required to
remove the hot-loop allocations identified by the review.

The full same-host [allocation-reuse benchmark](../benchmarks/allocation_reuse_v1.md) compared the
provenance-only baseline at `05630870a9e8a0b32cb46b59bf97441911b7de45` (two provenance commits
atop review base `e2b309b46c5369bbb556a8a15d3f7c27d9937f47`) with the candidate runtime at
`4972cd62b95b7f432e02e891e9ee9e3ad1c77cdc` on macOS arm64 using four fit workers. Both extensions
reported clean embedded build commits equal to their manifest source commits. All 40 recorded pairs
produced exact artifact and prediction digests. Across four matrix shapes and both growth
strategies, the aggregate native-time ratio was 1.0183 and aggregate incremental-RSS ratio was
0.9262. Median RSS was lower in all eight cases, by 3.0%-13.7%; shallow/tall native time was
7.3%-8.1% slower, while the aggregate remained inside the declared 3% timing and 5% RSS budgets.

### 2.8 Thread control

a positive integer requests exactly that many workers. Every native fit,

## 3. Inference performance

**Partially fixed in pending v0.12.11 PR.** Predictor tree loading now validates split feature
indices once at artifact load, collapses parent-relative stump deltas into tree-weighted absolute
branch contributions, and resets each loaded tree's runtime weight to `1.0` after the DART weight
has been folded in. Single-output and multiclass prediction loops now descend each tree to the
terminal selected branch and add one contribution per tree instead of accumulating every visited
node. Objective post-transform dispatch is cached as a small enum at load time instead of
string-matching `metadata.objective` for every prediction row.

Because this intentionally changes f32 addition ordering inside a tree, predictor/engine parity
tests now use a tight `1e-6` tolerance for trained multi-level fixtures rather than exact
bitwise equality.

## 5. Robustness / validation

**Fixed in pending v0.12.11 PRs.** `ModelMetadata` JSON decoding is now key-driven for
the current metadata schema, so artifacts no longer depend on the serializer's exact field order.
Required fields (`format_version`, `feature_names`, `trained_device`) are validated by key, while
`objective` and `num_classes` keep their existing backward-compatible defaults.

Unknown metadata fields are skipped as JSON values instead of rejected, so future metadata additions
do not break older readers when the current required schema fields are still present and valid. The
final follow-up replaces the remaining hand-rolled parser/serializer with a private `serde_json`
DTO, preserving unknown-field tolerance, duplicate known-field rejection, `objective` back-compat,
and omission of `num_classes` when it is absent.

**Fixed in pending v0.12.11 PR #130.** Predictor artifact loading bounds the per-tree
heap-style node slot array before allocation. Artifacts whose sparse local node IDs would require
more than `MAX_TREE_NODE_SLOTS` (65,536) predictor node slots for a single tree are rejected with a
contract violation instead of constructing a large mostly-empty `nodes_by_local_id` array.

The limit is a single shared constant, `alloygbm_core::MAX_TREE_NODE_SLOTS`, enforced on **both**
sides of the train/predict boundary so the contract is symmetric: the trainer's
`encode_tree_node_id` rejects any split whose heap child would land at slot
`>= MAX_TREE_NODE_SLOTS`, so a fit that would exceed the budget fails fast with a clear error
rather than emitting an artifact the predictor cannot load. This closes the asymmetry flagged in
review — previously the trainer permitted local node IDs up to the encoding stride (`1 << 20`),
16× larger than the predictor's cap, so a deep-but-legal tree could train yet fail to load. The
stride (`1 << 20`) is retained purely as the per-tree id multiplier; the slot budget is the
tighter, deliberately conservative bound (≈ depth 16, far more leaves than any realistic tree).

PR #130 completes the broader artifact boundary. Shared core limits now cover total artifact and
metadata bytes, sections and section payloads, features, stumps, classes/outputs, feature-name and
objective bytes, and per-feature cut counts. The serializer, `ModelIoContractV1` validator, and
deserializer enforce the same budgets. Counted optional sections validate count-derived lengths,
finite numeric values, ordering/uniqueness, and exact payload consumption before allocation.

Engine and predictor loaders now validate primary-tree feature references, multiclass metadata and
checked count arithmetic, predictor-layout agreement, DART/multi-output counts, linear-leaf and
native-categorical overlay references, and feature-baseline dimensions. Invalid overlays are
rejected instead of silently ignored. Scalar and multiclass tree sections must match their objective
metadata, and node-debug records are bounded, checked for unsupported flags and non-finite values,
and validated against model feature dimensions. Valid v1 and supported legacy artifact bytes remain
unchanged.

Adjacent public trust boundaries are hardened in the same PR: explicit dense and byte dimensions
use checked shape arithmetic before allocation or slicing; SHAP validates finite ordered quantile
and rank tables plus feature ranges; and Python `load_model(...)` surfaces a corrupt embedded native
artifact after both strict and compatibility loading fail instead of returning a fitted object with
no usable predictor.

### 5.4 Benchmark regression tracking in CI

**Fixed.** `benchmarks/perf_regression_benchmark.py` runs a fixed-seed, `n_jobs=1`
train+predict matrix (regression + binary, scalar and linear leaves) at sizes N
and 2N, gated inline in CI on `ubuntu-latest`/py3.13. Two gates: a hard,
platform-independent **quality** gate (the model must beat a constant predictor
by a healthy margin) and a loose, machine-independent **timing** gate (the
`fit(2N)/fit(N)` scaling ratio must stay below `3.0`, catching algorithmic
regressions such as O(N)→O(N²) without flaking on absolute runner speed).
Absolute wall-clock times are reported as descriptive deltas but not gated,
since they are not comparable across CI runners. Covered by
`benchmarks/tests/test_perf_regression_benchmark.py`.
